# Proposal: Shortener Public Origin

## Why

The `shortUrl` returned by the API was generated by the Symfony router from the incoming request's Host header. Behind the `frontend` nginx proxy, `proxy_set_header Host $host;` strips the port, so the dashboard displayed `http://localhost/<slug>` — a URL that cannot resolve (the SPA's catch-all answers `/<slug>` with `200 text/html`).

`DEFAULT_URI` cannot fix this: it only seeds the router request context for non-HTTP contexts (CLI, worker). `RouterListener` overwrites host and port from every live HTTP request.

## What Changes

The maintainer decided the **shortener has its own public origin**. The backend generates `shortUrl` from an explicitly configured `SHORTENER_BASE_URL`, independent of the request Host:

- New `SHORTENER_BASE_URL` env var: committed dev default `http://localhost:8080` in `backend/.env` and `backend/.env.example`, set on both `php` and `worker` compose services (matching the `DEFAULT_URI` precedent), and a distinctive `https://short.test` test value in `backend/phpunit.xml.dist` so tests prove the value comes from configuration, not from the request Host or `DEFAULT_URI`.
- `LinkController` composes the public URL as `<configured base>/<slug>` instead of using `UrlGeneratorInterface`; the now-unused router dependency is removed.
- The value is injected via a `_defaults.bind` in `backend/config/services.yaml`.
- OpenSpec delta requirements close the specification gap: `shortUrl` MUST be an absolute URL at the configured shortener origin and MUST resolve (302, or 410 when expired).

## Impact

- **Affected specs:** `specs/link-management/spec.md` (new resolvability requirement), `specs/dashboard/spec.md` (displayed short URL contract).
- **Affected code:** `backend/src/Controller/LinkController.php`, `backend/config/services.yaml`, env plumbing (`backend/.env`, `backend/.env.example`, `docker-compose.yml`, `backend/phpunit.xml.dist`).
- **Non-goal:** `frontend/nginx.conf` is deliberately not modified. With links pointing at the shortener origin, navigating `/<slug>` on the SPA origin is accepted, documented behavior, not a defect.
- Deployments must set `SHORTENER_BASE_URL` to the public shortener origin; the committed value is a dev default.
